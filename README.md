# Wurmz Manga API

A standalone Express + JavaScript (ESM) API that scrapes **Wurmz**
and serves normalized manga data. Auto-generated by the MANGA Pembuat API
Manga module (FASE 2 — Kode API Generator).

## Architecture

Layered, modular, and replaceable:

```
Route → Controller → Service → Fetcher → Parser → Normalizer → Cache
```

```
src/
├── routes/        # HTTP routing
├── controllers/   # Request/response handling
├── services/      # Business logic + cache orchestration
├── fetchers/      # HTTP fetching with retry + concurrency queue
├── parsers/       # cheerio HTML → raw objects
├── normalizers/   # raw objects → uniform schema
├── cache/         # in-memory LRU cache with TTL
├── middleware/    # error handler, CORS, rate limit
├── errors/        # AppError class + error codes
├── config/        # selectors.json + config.js
└── index.js       # app entrypoint
```

## Base URL

Setelah deploy, gunakan base URL berikut:

```
https://your-host/api
```

> Set `BASE_URL` di file `.env` sesuai URL hasil deploy agar dapat di-detect
> otomatis oleh MANGA.

## Endpoints

| Method | Path | Description |
| ------ | ---- | ----------- |
| GET | `/api/health` | Health check |
| GET | `/api/popular?page=&limit=` | Popular manga |
| GET | `/api/latest?page=&limit=` | Latest manga |
| GET | `/api/search?q=&page=&limit=` | Search manga |
| GET | `/api/manga/:slug` | Manga detail |
| GET | `/api/manga/:slug/chapters?page=&limit=` | Chapter list |
| GET | `/api/chapter/:slug` | Chapter detail |
| GET | `/api/chapter/:slug/pages` | Chapter pages |
| GET | `/api/img?url=&referer=` | Image proxy (bypass hotlink) |

## Response format

Success:

```json
{ "status": true, "data": {}, "pagination": { "page": 1, "limit": 20, "total": 100, "pages": 5 } }
```

Error:

```json
{ "status": false, "error": "ERROR_CODE", "message": "Human readable message", "details": "..." }
```

## Deployment

### Vercel
1. Push repository ke GitHub.
2. Import ke Vercel.
3. Set environment variables (`SOURCE_URL`, `BASE_URL`, `CORS_ORIGIN`).
4. Deploy. Base URL: `https://<project>.vercel.app/api`.

### Railway
1. Push repository ke GitHub.
2. Buat project baru di Railway dari repo ini (file `railway.json` sudah disertakan).
3. Set environment variables (`SOURCE_URL`, `BASE_URL`, `CORS_ORIGIN`).
4. Deploy. Start command otomatis: `npm start`.

### Render
1. Push repository ke GitHub.
2. Buat Web Service dari repo ini (file `render.yaml` sudah disertakan — Blueprint).
3. Set environment variables (yang `sync: false` diisi manual di dashboard).
4. Deploy. Health check: `/api/health`.

### Docker
```bash
docker build -t api-manga-wurmz .
docker run -p 3000:3000 -e SOURCE_URL=https://wurmz.net api-manga-wurmz
```
Atau gunakan `docker-compose.yml`:
```bash
SOURCE_URL=https://wurmz.net docker compose up --build
```

Setelah deploy, update `BASE_URL` di `.env` dengan URL hasil deploy, lalu
masukkan base URL tersebut di MANGA → Sumber Manga → Tambah API.

## Client Integration (FASE 5)

Folder `client/` berisi SDK siap-pakai untuk mengonsumsi API ini dari website
manapun tanpa menulis logika fetch:

| File | Fungsi |
| ---- | ------ |
| `client/client.js` | MangaAPIClient SDK — semua endpoint + cache in-memory |
| `client/reader.js` | Komponen reader long-strip (keyboard nav, slider, fullscreen) |
| `client/bookmarkManager.js` | Bookmark & riwayat baca (localStorage) |
| `client/styles.css` | Style dark/light, mobile-first |
| `client/example.html` | Contoh integrasi minimal |

Quick start:

```html
<script type="module">
  import MangaAPIClient from './client/client.js'
  import MangaReader from './client/reader.js'
  const api = new MangaAPIClient('https://your-host')
  const reader = new MangaReader('manga-reader', api, 'chapter-1')
</script>
```

Lihat `client/README.md` untuk detail endpoint & kontrol reader.
